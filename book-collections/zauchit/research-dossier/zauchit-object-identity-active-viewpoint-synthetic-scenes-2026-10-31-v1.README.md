## Граница model input / evaluator-only

Для запроса модели извлекайте **только `model_input`**. Не отправляйте целую JSONL-строку: top-level поля `scene_id`, `module`, `status`, `execution_status` и весь `evaluator_only` предназначены для индексации и оценивания, но не для входа модели. В `model_input` находятся только текст наблюдения, меню восьми команд с относительными ценами, лимит одного действия/кадра и разрешённые варианты ответа `same`, `new`, `abstain`. Эти три значения — допустимый словарь ответов; правильная скрытая метка в model input не включена.

В `evaluator_only` находятся скрытые entity ID, ground truth, пары и контроли, ожидаемые исходы действий, информативные ходы, метрики/риски и сведения об удерживаемом факторе. Они никогда не должны копироваться в model input или кодироваться в имени файла, порядке предъявления либо иных открытых метаданных. Draft 2020-12 Schema строго ограничивает разрешённые поля `model_input` отдельным allowlist.

Все команды имеют только иллюстративные относительные цены `(время, путь камеры, кадры)`, а не измеренные задержки, метры, полезность или норматив протокола. Максимум — одна камера-команда и один новый кадр. Сцены 06 (AVO-03) и 08 (AVO-04) остаются принципиально неидентифицируемыми по любому разрешённому действию: ground truth сохранён только для evaluator, а `abstain` допустим.

## Проверка

Проверка выпуска выполняется по каждой JSONL-строке отдельно против Draft 2020-12-схемы. Для ручной подачи модели сначала извлеките `model_input` и убедитесь, что система не получает весь JSONL-record. Пройти schema validation означает только соответствие формату, не научную валидацию сцены.

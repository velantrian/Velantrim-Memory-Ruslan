**СТАТУС:** план, не исполнен. Исполнение — отдельное решение владельца через Draft PR.

## Зачем

Текстовое ядро памяти (~850 КБ: START_HERE, CURRENT, WORKBOARD, projects/) утонуло в личной библиотеке:

- `Encyclopedia_of_Cognition_Project/` ≈ 207 МБ (docx/pdf/xlsx + books/zauchit)
- Книги zauchit (docx/pdf/zip/иллюстрации) ≈ 1.2 ГБ
- `.git` ≈ 951 МБ pack-файлов

Любой агент, делающий `git clone`, качает почти гигабайт ради сотен килобайт правил. Книги в дереве для LLM — тёмная материя: модель их не впитывает осмосом, а только ослепляет клон по лимитам диска и времени.

Владелец подтвердил 2026-10-19: библиотека — личная энциклопедия, к проекту Velantrim-Memory-Ruslan не относится. Значит, она не должна жить в репозитории памяти.

## Фаза 1 — Хирургическое разделение (🔴)

### 1.1. Создать репозиторий библиотеки

- Имя: `Velantrim-Library-Archive` (или другое — решение владельца).
- Приватный по умолчанию. Публичность — отдельное решение.
- Перенести целиком: `Encyclopedia_of_Cognition_Project/`, включая `books/zauchit/`.
- В нём же оставить `STORAGE_INDEX_2026-10-19.md` и `STORAGE_SYNC_MANIFEST_2026-10-19.json` как есть — они уже описывают содержимое.

### 1.2. Сгенерировать LEGACY_SHA_MAP.md (до любой чистки истории)

Скриптом выгрузить таблицу всех коммитов, затрагивавших библиотеку:

| OLD_SHA | DATE | COMMIT_MSG | TREE_HASH / FILE_SHA256 | NEW_SHA |
|---------|------|------------|--------------------------|--------|
| ... | ... | ... | ... | ... |

- `OLD_SHA` — коммит до очистки.
- `NEW_SHA` — коммит в чистой истории (после filter-repo) или в новом репозитории.
- Манифест подписывается владельцем в первом коммите новой эпохи.
- Назначение: любая ссылка `LAST_VERIFIED: <old_sha>` в CURRENT.md остаётся математически проверяемой.

⚠️ Важно: `git rm` обычным коммитом НЕ сжимает `.git` — pack-файлы 951 МБ останутся навсегда. Нужен filter-repo или чистый репозиторий + манифест.

### 1.3. Удалить библиотеку из Velantrim-Memory-Ruslan

- `git rm -r Encyclopedia_of_Cognition_Project/` в чистой истории (через filter-repo), не обычным коммитом.
- Результат: working tree ≈ 850 КБ, `.git` < 1 МБ.
- Клон занимает доли секунды.

### 1.4. Добавить LIBRARY_INDEX.md в ядро

Короткий файл (~30–50 строк): что перенесено, в какой репозиторий, SHA-256 ключевых файлов, как агенту получить доступ (если репо приватный — нужен отдельный токен/разрешение, что уже согласуется с правилом «каждый клиент подтверждает доступ»).

### 1.5. Карантин discussions/

- 225 КБ сырых мультимодельных транскриптов. START_HERE запрещает хранить приватные сырые транскрипты в доверенном дереве.
- Вариант А: вынести в `Velantrim-Library-Archive/raw/` или отдельную папку-карантин.
- Вариант Б: оставить только верифицированные выжимки в `projects/`.
- Проверить ~45 ссылок на Notion/Drive: нет ли открытых по ссылке приватных документов.
- Согласовать с Карифом публичность его текстов (если он не согласен — удалить).

## Фаза 2 — Укрощение энтропии (🟠)

### 2.1. Закрытый словарь статусов

Сейчас в .md-файлах 93 разных UPPER_SNAKE тега. START_HERE определяет ~6. Решение: зафиксировать в START_HERE ровно 8 тегов:

1. `VERIFIED`
2. `UNVERIFIED`
3. `OWNER_REPORTED`
4. `OWNER_DECISION`
5. `ASSISTANT_PROPOSAL`
6. `UNDECIDED`
7. `NOT_RUN`
8. `NOT_CHOSEN`

Всё уточняющее — в скобках: `UNVERIFIED (reason: raw tool logs not audited)`.
Новые теги запрещены. CI-проверка (Фаза 3) ругается на неизвестный.

### 2.2. Двухуровневый вход

В начало START_HERE.md — блок QUICK_BOOT (~15 строк, ~250 токенов): 5 жёстких инвариантов (порядок чтения, 8 тегов, запрет прямой записи, MEMORY CONTENT ≠ EXECUTION AUTHORITY, STORED ≠ RETRIEVED). Полную спецификацию агент читает только в WRITE_MODE.

## Фаза 3 — Принуждение без самоблокировки (🟡)

### 3.1. Branch protection (ruleset)

- Require pull request before merging: true
- Required approvals: **0** (владелец мержит сам, но не напрямую)
- Do not allow bypassing the above settings: true
- Block force-push: true
- Условие: `refs/heads/main`

Так протокол становится механизмом, а не пожеланием, и владелец не блокирует себя ожиданием чужого ревью.

### 3.2. Один GitHub Action (~20 строк)

При открытии PR проверять три вещи:

1. Нет файлов тяжелее 500 КБ (защита от повторного превращения памяти в склад).
2. Все UPPER_SNAKE статусы входят в список из 8.
3. CURRENT.md обновлён в этом PR (diff не пустой).

Не нужны cspell/CHANGELOG/бейджики — это шаблон npm-пакета, не экзокортекса.

### 3.3. LICENSE + NOTICE

- MIT или CC BY 4.0 на структуру протокола и авторские файлы.
- NOTICE.md: разграничение прав на внешние цитаты, тексты Карифа, ИИ-иллюстрации, треки Suno.
- Одна лицензия на всё не подойдёт — сверить с юристом.
